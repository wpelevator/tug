Control now backs itself up to the shared backup destination. Once `tug backup destination set` has run, control stores a consistent archive of its database, private CA and master key (without build images) in a `_control` restic repository every night, retries a failure after an hour and keeps 3 recent, 7 daily, 4 weekly and 6 monthly snapshots. The repository has its own password, derived from the master key like each project's, so a node that holds the destination credentials cannot read or forge it; `tug backup password --control` prints it for escrow. `tug backup list` shows a `control` line and `--check` fails when the control backup failed or is stale. `tug control restore --from-destination <url> --env …` rebuilds control on a fresh host from that repository using the destination credentials and the control password (`TUG_CONTROL_BACKUP_PASSWORD`), and `tug control backup --download [-o <file>]` saves a `0600` copy of a backup on your machine through the new `GET /api/v1/control/backups/:id/download`. Creating, downloading and reading the password of control backups are audited.
