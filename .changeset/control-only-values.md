`tug deploy` now takes every `${NAME}` from control and nothing from the machine that runs it. A value is a project secret (`tug secret`), a new project variable (`tug var set|list|remove|import`, for visible values such as image tags, hosts and ports, written with the `deploy` role), a per-deploy `--var NAME=value`, or the default in the Compose file. The shell environment, the `.env` next to the file, `env_file` entries and `COMPOSE_PROFILES` are no longer read (use `tug secret import .env` to move an existing file, `--profile` for profiles), and `--compose-cli` follows the same rule. A name is either a secret or a variable, and a secret is rejected outside `environment`, `command`, `entrypoint` and `healthcheck.test`. `tug deploy --dry-run` prints every referenced name with its source, each deployment records those sources (`values`, never a secret value), a rollback restores the earlier variable values, `tug secret set --from-file` stores exact contents such as a PEM key, and `tug secret import` stores a dotenv file as secrets (or as variables for the names you give `--vars`), without guessing from names or values. Database schema 3 adds `project_vars` and the deployment value record.
