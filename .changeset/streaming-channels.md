Streaming between agents, control and clients. Agents follow the Docker daemon's event stream, so a crashed, killed or unhealthy container is noticed within a second instead of at the next poll: crashes become `container.exited`, memory kills `container.oom`, an unhealthy health check `container.unhealthy`, and three crashes in five minutes one `container.crashloop` event, each rate-limited per service, and the agent reconciles at once. While their stream socket is open agents send events over it instead of one HTTP request each, and `status` and `GET /api/v1/nodes` report `connected`. New `GET /api/v1/watch` (WebSocket, `read` role, filtered to the credential's projects) pushes change hints and new events as they happen, and `GET /api/v1/events?after=<seq>` follows the event log (rows now carry `seq`; the response carries a `cursor` to pass as the next `after`, never beyond what the credential may read). An event from an agent now names a project only if that project places a service on that node (otherwise it is stored as a node-level event), and its fields are coerced and bounded. `tug tui` uses the channel: it shows `● live · push`, refetches only what changed, takes new events without a request and polls a quarter as often, and the nodes table gains a `LINK` column (`stream` or `poll`). Control reads `TUG_WATCH_TICK_MS` (default 1000). An older control without the channel keeps working.
