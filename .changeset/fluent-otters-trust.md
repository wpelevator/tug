'@wpelevator/tug': minor
---

Fail loudly on control version and credential/CA mismatches: every CLI command now does a one-request version preflight (`GET /api/v1/version`) per control per process and refuses — instead of surfacing a `404 Cannot GET /api/v1/services` on an older control — with `tug control setup <control host> --yes` as the remediation when the control is older than the CLI, and a pin hint (`npm i -g @wpelevator/tug@<version>`) when it is newer. TLS trust failures ("self-signed certificate in certificate chain") now name the credential's CA fingerprint and both fixes instead of a bare openssl string, on the HTTP and live channels alike, and `tug doctor` reports both fingerprints (credential CA vs presented server leaf) under a `control_server_cert` check. `tug init` and `tug control setup` name credential files by CA fingerprint (`<host>_<port>.<ca>.json`), so importing a credential from a different control CA is additive and never overwrites the credential the CLI was working with; `tug init` prints a notice naming both CAs when it re-points the CLI, and `control setup` refuses to import a root credential signed by a CA the control did not persist.
